Create `.keyly` files in `~/.config/keyly/templates/` to add custom shortcuts for any application.

## File Location

```
~/.config/keyly/
├── setting.conf
└── templates/
    ├── global.keyly
    ├── safari.keyly
    ├── vscode.keyly
    └── ...
```

`.keyly` files placed directly in `~/.config/keyly/` (the old location) are still loaded, for backward compatibility. If the same file name is in both places, Keyly uses the one you saved last.

<Aside type="tip">
Open the config folder quickly: click the **⚙︎ button** in the shortcuts window → **Open Config Folder** (it opens `~/.config/keyly/`; your `.keyly` files go in `templates/`)
</Aside>

## File Format

```keyly
# Sheet Name: My Shortcuts
# App: Safari

[Category Name]
> Optional description for this category
KEY+COMBO   Description of the shortcut
KEY+COMBO   Another shortcut
```

### Header Fields

| Field | Required | Description |
|-------|----------|-------------|
| `# Sheet Name:` | Optional | Internal label for the file (not shown in the window; the window title shows the app's name) |
| `# App:` | **Required** (except in `global.keyly`) | The app: its name (`Figma`), its bundle id (`com.figma.Desktop`) or its full path (`/Applications/Figma.app`) |
| `# Hide Default:` | Optional | `true` hides the app's own menu shortcuts, so only the ones in your file are shown |

Field names ignore upper and lower case. Keyly also matches a sheet by the app's name, so it keeps working when the app lives in `~/Applications`, comes from Setapp, or is a newer yearly version (a sheet for Adobe Photoshop 2024 also shows in Photoshop 2025).

### Other Directives

| Line | Description |
|------|-------------|
| `[Category]` | Starts a category; the shortcuts below it are listed under that name |
| `> description` | Sub-title for the current category (see [Category Descriptions](#category-descriptions)) |
| `# Group: Name - Description` | Groups the following categories into one card, with an optional description after ` - ` |
| `# Group: none` | Ends the current group |
| `\#`, `\[`, `\>` | A shortcut whose key starts with `#`, `[` or `>` (see [Keys that look like syntax](#keys-that-look-like-syntax)) |

### Shortcut Lines

Each shortcut line can be written in one of two forms:

```keyly
CMD+SHIFT+T    Reopen last tab
⇧⌘T | Reopen last tab
tool attach <name> | Attach to a session
```

- **Whitespace form:** the key combo and the description are separated by a tab or two or more spaces (if there is none, the first space is used).
- **`|` form:** everything before `|` is the shortcut, everything after it is the description. Use it when the shortcut itself contains spaces, such as a terminal command.

### Key Modifiers

| Modifier | Symbol |
|----------|--------|
| `CMD` or `COMMAND` | ⌘ Command |
| `SHIFT` | ⇧ Shift |
| `OPT`, `OPTION` or `ALT` | ⌥ Option |
| `CTRL` or `CONTROL` | ⌃ Control |

Combine modifiers with `+`. They are shown in the macOS order (⌃⌥⇧⌘), whatever order you write them in:
- `CMD+C` → ⌘C
- `CMD+SHIFT+T` → ⇧⌘T
- `CMD+OPT+ESC` → ⌥⌘esc

Named keys are converted too: `ENTER`/`RETURN` → ⏎, `TAB` → ⇥, `DELETE`/`BACKSPACE` → ⌫, `FWDDEL` → ⌦, `UP`/`DOWN`/`LEFT`/`RIGHT` → ↑↓←→, `HOME` → ↖, `END` → ↘, `PGUP` → ⇞, `PGDN` → ⇟, `F1`–`F20`, plus `ESC`/`ESCAPE` and `SPACE`.

Mouse actions keep their `+` so they still read as a combination: `⌘+click`, `⌥+drag`.

### Keys that look like syntax

Lines starting with `#`, `[` or `>` are comments, categories and descriptions. To list a shortcut whose key starts with one of those characters, put a `\` in front of it:

```keyly
[Markdown]
\#              Heading 1
\##             Heading 2
\>              Quote block
\[x]            Checked box
```

A `\` on its own, followed by spaces, is simply the backslash key.

## Global Shortcuts

Shortcuts in `~/.config/keyly/templates/global.keyly` are shown for every app. This is the place for system shortcuts such as `⌘Tab` or `⌘Space`, which are not in any app's menu bar. It uses the same `[Category]`, `# Group:` and shortcut-line syntax, without an `# App:` line. `> description` lines in `global.keyly` are not shown, so they never label an app's own menu categories.

## Category Descriptions

Add a description line after `[Category]` using `>` prefix:

```keyly
[Chat]
> Focus on chat panel first.
CMD+L       Focus Chat
CMD+I       Open Composer
```

The description appears as a sub-title below the category name in the shortcuts window. This is useful for providing contextual hints.

## Complete Example

```keyly
# Sheet Name: My Shortcuts
# App: Safari

[Navigation]
> Essential navigation shortcuts
CMD+L       Open Location
CMD+T       New Tab
CMD+SHIFT+T Reopen Last Tab
CMD+[       Go Back
CMD+]       Go Forward

[Bookmarks]
> Manage your bookmarks
CMD+D       Add Bookmark
CMD+SHIFT+B Show All Bookmarks

[Tabs]
> Tab management shortcuts
CTRL+TAB    Next Tab
CTRL+SHIFT+TAB Previous Tab
CMD+W       Close Tab
CMD+SHIFT+W Close Window
```

## Creating a Config File

<Steps>
1. Open Terminal

2. Create the config directory (if it doesn't exist):
   ```bash
   mkdir -p ~/.config/keyly/templates
   ```

3. Create a new `.keyly` file:
   ```bash
   nano ~/.config/keyly/templates/myapp.keyly
   ```

4. Add your shortcuts following the format above

5. Save the file. Keyly reloads it automatically (if the change doesn't show, use **⚙︎ → Reload Config** in the shortcuts window)
</Steps>

## Tips

- **One file per app** keeps things organized, but you can use any naming convention
- **Categories** help group related shortcuts (use `[Category Name]` syntax)
- **Comments** start with `#` and are ignored (except the directives above). A line starting with `##` is always a comment, so `## App: …` turns a directive off
- **Separate** the key combo and description with a tab or two or more spaces, or use `|` when the shortcut contains spaces
- **Changes apply automatically** when you save a file; **⚙︎ → Reload Config** reloads manually

## When Something Is Wrong

A line Keyly can't read is skipped, and the rest of the file keeps working. Keyly never stops because of a mistake in a file.

Problems are listed in the shortcuts window under **⚙︎ → ⚠︎ config problems**, for example `figma.keyly line 12: …`. Click one to open the file at that line (VS Code jumps straight to it). The same messages appear in the Console app if you search for `com.keyly`.

## Troubleshooting

### Shortcuts not appearing?

1. Open **⚙︎ → ⚠︎ config problems** in the shortcuts window and fix anything listed for your file
2. Check the `# App:` line. The simplest form is the app's name as Finder shows it, such as `# App: Safari`
3. Reload with **⚙︎ → Reload Config** in the shortcuts window

### Not sure what to write in `# App:`?

Use the app's name, or its bundle id, which never changes when the app moves or is renamed:
```bash
osascript -e 'id of app "Safari"'
# com.apple.Safari
```

## Using Templates

Don't want to write configs from scratch? Use community templates:

```bash
curl -fsSL https://raw.githubusercontent.com/hoaiphongdev/keyly/main/scripts/install-templates.sh | bash -s -- -t cursor.keyly
```
